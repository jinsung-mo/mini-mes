# web: 단말 화면 (WEB tier)

현장 단말에서 쓰는 MES 화면입니다. **레거시 WAS의 응답 계약에 맞춰 만든 클라이언트**이고, Java로 전환한 뒤에도 이 화면은 고치지 않습니다.

## 실행

```bash
docker compose up -d                                  # 레포 루트에서. PostgreSQL + nginx
cd legacy-csharp/LegacyMes && dotnet run              # C# 레거시 WAS (:5080)
```

브라우저에서 http://localhost:3000 을 엽니다.

## 구조

```
브라우저 ── http://localhost:3000 ──▶ nginx (컨테이너)
                                      ├─ /              → 화면 파일 (html/)
                                      ├─ /legacy/api/.. → host.docker.internal:5080 (C# 레거시)
                                      └─ /java/api/..   → host.docker.internal:8081 (Java)
```

| 파일 | 내용 |
|---|---|
| [`nginx.conf`](nginx.conf) | 화면 파일 제공, 경로 앞부분을 보고 WAS로 요청을 넘김 |
| [`html/index.html`](html/index.html) | 화면 뼈대 |
| [`html/app.js`](html/app.js) | 서버 호출, 화면 그리기, API 로그, 응답 비교 |
| [`html/style.css`](html/style.css) | 스타일 |

화면 코드는 상단의 WAS 스위치로 `/legacy`와 `/java` 중 무엇을 붙일지만 고릅니다.
브라우저 입장에서는 모든 요청이 같은 주소(`localhost:3000`)로 가기 때문에 CORS 설정도 필요 없습니다.

## 화면 구성

- **상단**: 공장 선택, 공장 현지 시각, WAS 스위치(점 색: 초록 정상 / 주황 서버는 떴지만 API 미완성 / 빨강 응답 없음)
- **작업지시**: 생성, 상태 필터, 목록
- **상세**: 상태 전이 버튼, 실적 보고, LOT 목록, 실적 이력
- **API 로그**: 화면이 보낸 요청과 받은 응답. 조회(GET)는 C#과 Java에 같은 요청을 보내 응답을 비교할 수 있습니다.

## 직접 해 볼 것

1. **기본 흐름**: 울산 공장에서 작업지시를 만들고 릴리즈 → 작업 시작 → 실적 보고까지 해 봅니다. API 로그를 펼쳐서 화면이 실제로 어떤 JSON을 주고받는지 확인합니다.
2. **검증은 WAS가 한다**: 상태에 맞지 않는 버튼(파란색이 아닌 버튼)을 눌러 봅니다. 화면은 막지 않고, WAS가 `E005`로 거절합니다.
3. **시간대 버그**: 앨라배마 공장에서 보고 시각을 08:00으로 두고 실적을 보고합니다. 기대값은 A조인데 레거시는 C조로 계산합니다. 화면이 보내는 값(`...-05:00`)은 맞는데, 서버가 그걸 서버 시간으로 바꿔서 계산하기 때문입니다.
4. **WAS가 없으면**: WAS 스위치를 Java로 바꿔 봅니다. 아직 Java WAS가 없어서 nginx가 502를 돌려줍니다.

2단계에서 Java WAS를 만든 뒤에는 이렇게 확인합니다.

5. **같은 화면, 다른 WAS**: Java로 바꿔도 화면이 똑같이 동작하는지 확인합니다. API 로그의 비교 버튼으로 두 WAS의 응답이 같은지 봅니다.
6. **섞어서 쓰기**: C#으로 작업지시를 만들고, Java로 작업을 시작하고, 다시 C#으로 실적을 보고해 봅니다. 같은 DB와 같은 계약을 쓰니까 섞어도 됩니다.
   실무에서도 이 원리로 API를 하나씩 새 시스템으로 옮깁니다. 앞단(여기서는 nginx)에서 옮긴 API만 새 시스템으로 보내는 방식으로, Strangler Fig 패턴이라고 부릅니다.

## 왜 조회(GET)만 비교하나

등록·변경(POST)을 두 WAS에 똑같이 보내면 같은 DB에 두 번 반영됩니다. 작업지시가 두 개 생기거나 수량이 두 번 더해집니다.
그래서 화면에서는 조회만 비교하고, 등록·변경까지 포함한 비교는 3단계에서 DB를 분리해 자동으로 합니다.
